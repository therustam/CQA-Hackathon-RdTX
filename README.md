# CQA — Conversation Quality Analytics

Прототип для хакатона Freedom Broker: оценка работы оператора поддержки (чаты и звонки; RU, KZ, EN) по настраиваемому чек-листу. Модель отвечает по каждому критерию и ссылается на реплику-основание, код считает баллы и итог, специалист оспаривает критерий, проверяющий принимает решение — итог пересчитывается, исходная оценка ИИ сохраняется.

| Функция | Где в интерфейсе |
|---|---|
| 01 Создать чек-лист | «Чек-лист»: критерии, формулировки, вес, тип (Да/Нет, шкала, флаг), N/A и его условие, ступени шкалы, секции → «Сохранить версию» / «Сохранить и применить» |
| 02 Оценить диалог | «Диалоги»: импорт по `group_id` или «Загрузить JSON», затем «Оценить» в строке, в карточке или «Оценить набор» |
| 03 Показать результат | Карточка: ответ, баллы, вес и перераспределённый вес, объяснение, реплики-основания, проверенный участок, причина N/A, секции, итог, отдельная полоса грубой ошибки |
| 04 Открыть карточку | Клик по строке списка; клик по `m12` прокручивает к реплике, у звонков — перематывает запись |
| 05 Подать апелляцию | Роль «Специалист» → «Оспорить» у критерия → комментарий |
| 06 Принять решение | Роль «Проверяющий» → «Апелляции» или «Рассмотреть апелляцию» в карточке → подтвердить / изменить с причиной |

## Запуск

Нужен Python 3.11+ (разбор ISO-меток времени с 7 знаками дробной части).

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows;  source .venv/bin/activate — macOS/Linux
pip install -r requirements.txt
copy .env.example .env            # cp .env.example .env — macOS/Linux; затем заполните .env
python -m uvicorn app.main:app --reload
```

Откройте http://127.0.0.1:8000.

В `.env`:
- `OPENAI_API_KEY` или `ANTHROPIC_API_KEY` — ключ выбранного провайдера; при наличии обоих используется OpenAI. Без ключа работает всё, кроме новой оценки.
- `CQA_SOURCE_URL` — ссылка «Открыть GET для DEV» со стр. 3 гайда **без** `&group_id=DEV`. `group_id` вводится в интерфейсе.
- `CQA_MODEL` (по умолчанию `gpt-6-luna` для OpenAI или `claude-opus-5-5` для Anthropic), `CQA_EFFORT` (`medium`), `CQA_DB` (`cqa.db`).

Тесты (ключ не нужен, модель подменяется): `python -m pytest -q`.

Выгрузка для сдачи: `python -m scripts.export_results --group DEV --out results/dev/results.json --expect 65`.
Для контрольного набора укажите выданный `group_id`, путь `results/prod/results.json` и `--expect 10`; `--fetch --evaluate` добавляются для получения и оценки данных.
Скрипт проверяет формат организаторов до замены файла. Неполный/неверный формат завершает команду ошибкой; законные записи `status="error"` сохраняются с исходными ID. Для экспорта нужны `CQA_TEAM_NAME` и название использованной модели.
Повторный импорт изменённого корректного транскрипта под прежним ID отклоняется, чтобы сохранить доказательства старых оценок.

## Контрольный набор (23-й час) и замена критерия

1. «Диалоги» → ввести `group_id`, выданный организаторами → «Импортировать».
2. Выбрать набор → «Оценить набор». Прогресс, ошибки и стоимость видны в полосе сверху; уже оценённые диалоги пропускаются, упавшие можно перезапустить той же кнопкой.
3. Замена критерия: «Чек-лист» → изменить или удалить критерий, «Добавить критерий» → «Сохранить и применить к набору …». Сохраняется новая версия v2, по ней запускается пакетная оценка; результаты v1 остаются доступны через выбор версии.

## Модель и стоимость

- Модель выбирается по ключу: **OpenAI `gpt-6-luna`** ($0,10 / 1M входных токенов, $0,01 из кэша, $0,50 / 1M выходных; рассуждения — `CQA_EFFORT`) или **Claude Opus 5.5** (`claude-opus-5-5`, $4 / 1M входных токенов, $20 / 1M выходных).
- Один вызов на диалог со structured output; повтор — только если ответ не прошёл проверку.
- Стоимость считается по фактическому расходу токенов каждой оценки и показывается в карточке, в списке (средняя) и в пакетном прогоне.
- По сохранённому прогону DEV v2 (65 успешных оценок, 2026-11-07): расчётная сумма **$0,06315**, в среднем **$0,00097 за диалог**, диапазон $0,00059–0,00177. Расчёт использует записанный расход токенов, включая автоматические повторы в оценке, и тарифы из `app/llm.py`; это оценка стоимости, не выписка провайдера. Отдельные прежние переоценки в сумму этого прогона не включены.

## Как это устроено

```
web/ (HTML/CSS/JS, #cqa-root)  ──fetch──>  FastAPI app/main.py
                                              ├─ importer.py   GET организаторов по group_id / загрузка JSON
                                              ├─ transcript.py ID реплик, сортировка, удержание, смещения в записи
                                              ├─ prompt.py     промпт из сохранённого чек-листа
                                              ├─ llm.py        OpenAI/Claude: structured output, кэш промпта, стоимость
                                              ├─ evaluator.py  проверка ответа + один повтор
                                              ├─ scorer.py     баллы, N/A, секции, итог (Decimal, half-up)
                                              └─ db.py         SQLite: диалоги, версии чек-листа, оценки, апелляции
```

Модель возвращает только ответы и ID реплик; все числа считает `scorer.py`, поэтому итоги воспроизводимы, а апелляция — это override поверх неизменной оценки ИИ. Подробности решений — `docs/decisions.md`.

API: `GET /docs` (OpenAPI). Основное: `POST /api/import`, `POST /api/upload`, `GET /api/conversations`, `GET /api/conversations/{id}`, `GET /api/conversations/{id}/audio`, `POST /api/evaluate`, `POST /api/batch`, `GET|POST /api/checklists`, `POST /api/evaluations/{id}/appeals`, `GET /api/appeals`, `POST /api/appeals/{id}/decision`.

## Подсчёт (стр. 2 чек-листа)

«Да» — полный вес, «Нет» — 0; ступень шкалы → `вес × ступень / верхняя ступень`. Критерии с N/A исключаются, веса остальных нормируются к 100. Итог округляется до двух знаков (half-up); если применимых критериев с весом нет — итога нет. Грубые ошибки — отдельный флаг без баллов. Наш проверочный пример по правилам стр. 2 (02 и 07 — N/A, 70,5 из 80) даёт **88,13** — это юнит-тест.

## Встраивание в Dynamics 365

Интерфейс — три файла (`web/index.html`, `web/cqa.css`, `web/js/cqa.js`) и шрифты `web/fonts/`. Всё монтируется в один элемент:

```js
import { mount } from "./js/cqa.js";
mount(document.getElementById("cqa-root"), { apiBaseUrl: "https://<сервер-cqa>" });
```

Классы с префиксом `cqa-`, стили ограничены корнем, глобальных переменных нет, маршрутизация по `#hash` внутри веб-ресурса. Для другого origin на бэкенде нужно включить CORS для домена CRM.

## Точность

Локальная проверочная разметка — `data/gold.json` (формат и ограничения в `data/README.md`). Согласие по критериям и языкам выводится в терминал: `python -m scripts.bench --checklist 2`.

Текущая локальная разметка предварительная, составлена агентом и требует подтверждения специалистом. Её согласие с моделью нельзя выдавать за точность на всём DEV или PROD.

## Готовность к защите и сдаче

Шесть функций из гайда реализованы. Для репетиции: открыть диалог → показать ответ, доказательство, N/A и итог → подать апелляцию → сменить роль и принять решение → изменить критерий и применить новую версию к выбранному набору. Общий лимит демонстрации — 5 минут.

DEV-файл должен содержать все 65 исходных ID. Контрольный файл создаётся после получения организаторского набора: ровно 10 ID, включая записи с ошибкой обработки. Публичный Git-репозиторий, оба файла результатов и последний commit/push должны быть готовы до стоп-кода; локальный успешный экспорт этого не заменяет. Изменение критерия проверяется отдельно через настройки, прежняя версия остаётся доступной для официальной выгрузки.

Полная установка внутри Dynamics 365, авторизация, RAG и анализ интонации не нужны для текущего задания. Аудио необходимо, только если заменённый критерий оценивает голосовые свойства; текущий оценщик передаёт LLM транскрипт, поэтому такую оценку нельзя заявлять без доработки.

## Структура

```
app/         бэкенд (FastAPI)
contracts/   default_checklist.json (единственное место с текстами критериев), llm_output.schema.json
web/         интерфейс
tests/       pytest: подсчёт, транскрипт, промпт, проверка ответа, API-сценарии
scripts/     bench.py — согласие с эталоном
docs/        PLAN.md (план хакатона), decisions.md, checklist.pdf
data/        локальные данные (не в git)
```

Данные DEV содержат реальные звонки и подписанные ссылки на записи, поэтому в репозиторий не входят: интерфейс загружает их по `group_id` через бэкенд.
