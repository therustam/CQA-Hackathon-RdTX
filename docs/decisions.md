## Исправления после аудита 2026-11-07

- Финальный итог отсутствует, пока не получены все критерии. missing отличается от N/A; строки частичного ответа остаются доступны для проверки.
- Повторный пакет обрабатывает error и needs_review. Успешной считается последняя попытка со статусом ok; экспорт предпочитает последнюю успешную оценку, а при её отсутствии передаёт ошибку с исходным ID.
- Формат сдачи 1.0 проверяется относительно исходного default_checklist.json. Произвольные чек-листы по-прежнему применимы внутри приложения, но их результаты нельзя выдать за официальный формат, если изменились коды, шкалы или итог.
- Корректный транскрипт и принадлежность набору при повторном импорте неизменяемы. Конфликт отклоняется; обновление ссылки аудио допускается. Непригодный источник с известным ID сохраняется как import_error, чтобы не потерять error-запись; его можно заменить исправленным источником.
- Порядок решений апелляций хранится отдельно как decision_order и назначается транзакционно. Сравнивается текущая эффективная оценка, поэтому повторная апелляция может вернуть исходное значение ИИ. Исходный raw не меняется.
- Предварительная разметка агентом хранится локально, отдельно от исходных оценок. Согласие с ней не является подтверждённой точностью; ограничения и спорные случаи описаны в data/README.md. Временные отчёты после работы удаляются.

Решения, принятые при сборке, и их обоснование. Спорные трактовки критериев (карта случаев из PLAN.md 1.8.4) P3 дописывает сюда же — промпт берёт правила только из чек-листа, поэтому принятое решение нужно перенести в поле `guidance` нужного критерия через редактор.

## Подсчёт

- **Округление** — итог считается из точных промежуточных значений через `Decimal` + `ROUND_HALF_UP` (88,125 → 88,13). Отображаемые баллы и веса округляются до двух знаков отдельно и не используются для пересчёта итога. Проверено тестом на нашем примере по правилам стр. 2.
- **N/A** исключает критерий; веса применимых критериев нормируются к 100. Если применимых критериев с весом нет — итога нет (`null`, в UI «—»).
- **Секции** — набранные / доступные перераспределённые баллы и процент; секция только из N/A или флагов показывает «—».
- **Флаг (08)** — тип `flag`, вес всегда 0, в итог не входит; показывается отдельной красной полосой с подтипом и репликой.
- **Сумма весов ≠ 100** в отредактированном чек-листе допускается (итог всё равно нормируется), редактор подсвечивает сумму.

## Модель и промпт

- **Модель**: провайдер выбирается по ключу (`OPENAI_API_KEY` имеет приоритет над `ANTHROPIC_API_KEY`), по умолчанию `gpt-6-luna` (с 2026-11-07, вместо `gpt-4o-mini`: новее и дешевле) или `claude-opus-5-5`; structured output использует `contracts/llm_output.schema.json`. Модель отвечает только `applicable / answer / step / explanation / evidence_ids / checked_range / na_reason / confidence`; все числа считает `app/scorer.py`.
- **Промпт компилируется из чек-листа** (`app/prompt.py`): общая преамбула о формате данных + `instructions` чек-листа + блок на каждый критерий (правило, условие N/A, подсказка `guidance`, ступени, подтипы). В коде нет ни одного названия или правила критерия — это проверяет тест `test_no_criterion_wording_in_code`.
- **Кэширование**: system-промпт зависит только от версии чек-листа и помечен `cache_control`, поэтому в пакете он оплачивается почти один раз.
- **Отказ модели** (`stop_reason=refusal`): включён серверный fallback `fallbacks="default"` (бета `server-side-fallback-2026-07-01`) для моделей, которые его поддерживают.
- **Валидация ответа**: неизвестные ID реплик, N/A там, где он запрещён, ступень не из шкалы, неизвестный подтип, пропущенный критерий → один автоматический повтор с перечнем ошибок; если и он не прошёл — статус «Нужна проверка», некорректные пункты отбрасываются.
- **Объяснения на русском, цитаты на языке оригинала.**

## Транскрипт

- ID реплик `m0…mN` = индекс в исходном массиве; UI показывает исходный порядок и исходные метки времени.
- В промпт идёт стабильная сортировка по времени без точных дублей (p4-ru-001) и с пометкой пауз ≥ 60 с.
- **Удержание** (p4-ru-002): реплики оператора между «Клиент находится на удержании» и «…больше не находится на удержании» помечаются как внутренняя консультация.
- **Первая реплика оператора** передаётся модели как подсказка (бот всегда здоровается первым).

## Звонки и аудио

- `audio_url` возвращает HTML-страницу плеера Power Automate со ссылкой на mp3, подписанной на 1 час. Бэкенд (`/api/conversations/{id}/audio`) достаёт свежую ссылку и делает редирект; кэш 45 минут. mp3 поддерживает Range-запросы, поэтому `<audio>` перематывается. Ссылка «Открыть запись» использует `?player=true` и ведёт прямо к исходному плееру, независимо от успешности разбора HTML для встроенного аудио.
- **Смещение реплики в записи** = время от события «Запись и транскрибирование запущены» минус паузы записи («приостановлены» → «возобновлены»). Проверено на всех 5 звонках DEV по длительности mp3 (из Xing-заголовка): расхождение 1–7 с, перемотка встаёт на нужный фрагмент (в худшем случае на несколько секунд раньше). UI дополнительно перематывает на 1 с раньше реплики.

## Данные и безопасность

- `data/dev.json` (DEV-набор с 5 реальными звонками и подписанными ссылками на записи), исходная ссылка API и `guide.pdf` (кнопка в PDF содержит подписанную ссылку DEV) **не коммитятся**. Ссылка API — в `.env` (`CQA_SOURCE_URL`), `group_id` вводится в интерфейсе.
- Загрузка JSON и импорт валидируют записи (ID, роли, текст, `audio_url` только `https://`); некорректные записи отклоняются с причиной.

## Апелляции

- Результат ИИ неизменяем. Решение проверяющего хранится в апелляции как override по критерию; итог пересчитывается тем же `scorer.score(checklist, raw, overrides)`. В карточке видны исходная оценка, решение с причиной и финальный итог.
- Одна открытая апелляция на критерий; решение требует причину; «Изменить» допускает только ответы, разрешённые типом критерия (N/A — только если разрешён).

## Интерфейс

- Чистые HTML/CSS/JS-модули, одна точка монтирования `#cqa-root`, классы с префиксом `cqa-`, единственный объект конфигурации `{ apiBaseUrl }` — готово к упаковке в веб-ресурс Dynamics 365.
- Направление «клиническая карта»: зелёная полоса показателей, транскрипт как хронология, результаты как таблица находок; цвет никогда не единственный носитель статуса.
- Шрифт Golos Text (OFL) хранится локально — кириллица и казахские буквы, без внешних запросов.
